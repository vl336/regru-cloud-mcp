# regru-cloud-mcp

Read-only MCP-сервер для **Рег.облака** (облачные серверы Reg.ru, [CloudVPS API](https://developers.cloudvps.reg.ru)).

Работает с **любым MCP-совместимым клиентом** (Claude Desktop, Cursor, ZCode, Windsurf и др. — всё, что умеет подключать stdio MCP-серверы). Позволяет агенту безопасно, **только для чтения**, отвечать на вопросы:

- сколько денег осталось на балансе облака и на сколько их хватит;
- что потребляет баланс — детализация по каждому ресурсу (серверы, управляемые БД, плавающие IP и т.д.);
- какие серверы подняты, их статус, конфигурация (CPU/RAM/диск/ОС), IP-адреса, регионы;
- цены ресурсов за час/месяц, список снэпшотов и SSH-ключей.

Мутирующих операций нет принципиально: сервер обращается только к GET-эндпоинтам API.

## Инструменты

| Инструмент        | API-эндпоинт          | Что возвращает                                                                 |
| ----------------- | --------------------- | ------------------------------------------------------------------------------ |
| `cloud_balance`   | `GET /v1/balance_data`| Баланс, бонусный баланс, hourly/monthly cost, days/hours left, детализация потребления |
| `cloud_servers`   | `GET /v1/reglets`     | Все серверы: статус, ОС, тариф, vcpus/memory/disk, IP, PTR, регион, бэкапы      |
| `cloud_server`    | `GET /v1/reglets/{id}`| Один сервер подробно (+ фактическое использование диска)                        |
| `cloud_prices`    | `GET /v1/prices`      | Прайс-лист всех ресурсов (час/месяц)                                            |
| `cloud_snapshots` | `GET /v1/snapshots`   | Снэпшоты: имя, размер, базовый образ                                            |
| `cloud_ssh_keys`  | `GET /v1/account/keys`| SSH-ключи: имя, fingerprint, публичный ключ                                     |

## Где взять токен

Панель управления **Облачными серверами** Рег.облака → вкладка **«Настройки»** → API-токен (или Личный кабинет reg.ru → Облачные серверы → Настройки).

> ⚠️ Токен открывает **полный** доступ к вашим облачным VPS (создание/удаление и т.д.).
> Держите его в секрете; при компрометации смените его там же в панели.
> Этот MCP-сервер, в отличие от токена, ничего менять не умеет — только читать.

## Установка в MCP-клиент

Токен передаётся через переменную окружения `REGRU_CLOUD_TOKEN` в настройках MCP-сервера вашего клиента — её подставляет сам клиент при запуске процесса, и она не попадает в контекст модели. Сервер не логирует токен и не возвращает его в результатах инструментов.

Универсальный сниппет (формат `mcpServers` — одинаков в Claude Desktop, Cursor и большинстве клиентов):

```json
{
  "mcpServers": {
    "regru": {
      "command": "npx",
      "args": ["-y", "github:vl336/regru-cloud-mcp"],
      "env": {
        "REGRU_CLOUD_TOKEN": "<ваш API-токен>"
      }
    }
  }
}
```

Куда положить сниппет:

| Клиент         | Конфигурационный файл                                                       |
| -------------- | --------------------------------------------------------------------------- |
| Claude Desktop | macOS: `~/Library/Application Support/Claude/claude_desktop_config.json`<br>Windows: `%APPDATA%\Claude\claude_desktop_config.json` |
| Cursor         | `~/.cursor/mcp.json` (или Settings → MCP)                                   |
| ZCode          | `~/.zcode/cli/config.json` — секция называется `mcp.servers` вместо `mcpServers` |

После правки конфига перезапустите клиент.

> Локальных путей в конфиге нет: `npx` скачивает и собирает сервер прямо из этого репозитория. Нужен установленный Node.js ≥ 18 и git в PATH.

### Альтернативные способы установки

Через глобальную установку (работает офлайн, старт быстрее):

```bash
npm install -g github:vl336/regru-cloud-mcp
```

```json
{
  "mcpServers": {
    "regru": {
      "command": "regru-cloud-mcp",
      "env": { "REGRU_CLOUD_TOKEN": "<ваш API-токен>" }
    }
  }
}
```

Если пакет опубликован в npm — можно писать просто `"args": ["-y", "regru-cloud-mcp"]`.

## Разработка

```bash
git clone https://github.com/vl336/regru-cloud-mcp && cd regru-cloud-mcp
npm install
npm run build     # компиляция в dist/
npm run smoke     # см. ниже
```

### Smoke-тест

Выполняет пару реальных read-only запросов (баланс + первые серверы) и печатает результат. Токен читается **только** из переменной окружения процесса:

```bash
# Git Bash / Linux / macOS
REGRU_CLOUD_TOKEN=<токен> npm run smoke

# Windows CMD
set REGRU_CLOUD_TOKEN=<токен> && npm run smoke
```

Переменные окружения:

| Переменная             | Назначение                                        |
| ---------------------- | ------------------------------------------------- |
| `REGRU_CLOUD_TOKEN`    | обязательный API-токен Рег.облака                 |
| `REGRU_CLOUD_API_BASE` | необязательный base URL (по умолчанию `https://api.cloudvps.reg.ru`) |

## Contributing

Хотите пользоваться и что-то доработать под себя — добро пожаловать:

1. **Нашли баг или не хватает метода API** — откройте [issue](https://github.com/vl336/regru-cloud-mcp/issues): что делали, что ожидали, что получилось (токены и персональные данные не прикладывать).
2. **Хотите предложить изменение** — стандартный flow:
   - форкните репозиторий и создайте ветку (`git checkout -b feature/my-tool`);
   - внесите изменения; для нового инструмента добавьте его в `src/tools.ts` (и в таблицу инструментов в README);
   - `npm install && npm run build` — сборка должна проходить без ошибок;
   - опционально проверьте на своём токене через smoke-тест (токен в PR не попадает — он читается только из вашего окружения);
   - откройте Pull Request с кратким описанием «что и зачем».
3. **Правила проекта** (короткие, но важные):
   - 🔒 **Только read-only**: сервер ходит исключительно в GET-эндпоинты CloudVPS API. PR, добавляющие мутирующие операции, не принимаются — это принцип дизайна;
   - 🔑 **Никаких секретов в коде**: токены только через переменные окружения; в README и тестах — только плейсхолдеры;
   - стилем кода считается то, что уже в репозитории — минимальные зависимости, TypeScript strict.
